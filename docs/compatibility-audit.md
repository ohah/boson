# HTML·CSS·JavaScript API 적대적 검증 기록

2026-09-27 기준의 **설계 문서 검토**다. 구현 동작이나 웹 표준 전체 호환을 검증한 결과가 아니다. 수정 대상은 [HTML·CSS 대응표](https://macstudio.tailed42f2.ts.net/spinon/compatibility.html), [JS API 대응표](https://macstudio.tailed42f2.ts.net/spinon/js-api.html), [모바일 실행 구조도](https://macstudio.tailed42f2.ts.net/spinon/runtime.html)다.

| 회차 | 적대적 질문 | 발견한 빈틈 | 보강 결과 |
| --- | --- | --- | --- |
| 1. HTML 의미 | 화면에 보이면 웹 태그와 같다고 오해할 수 있는가? | `form`·`label`·`textarea`·`select`, 식별·포커스 속성, 기본 동작과 이벤트 전파 범위가 없었다. | 미지원 태그 진단과 후속 계약, 속성별 처리, 버블링·취소·접근성 검증 조건을 추가했다. |
| 2. CSS 계산 | 파싱 성공을 렌더링 지원으로 오해할 수 있는가? | 블록·인라인 기본값, 계단식 순서, 단위·변수·반응형, 폰트·이미지 측정, 동적 시각 상태가 한 항목에 뭉쳐 있었다. | 계산 단계별 경계와 미지원 진단 기준을 별도 표로 만들었다. |
| 3. JS 실행 | V8 내장을 브라우저 전역 API로 오해할 수 있는가? | 로그, 바이너리 업로드, 보안 난수, 연결형 네트워크, Worker, Canvas의 상태가 빠져 있었다. | 엔진·호스트·동작 차이·초기 제외 영역에 각각 배치했다. |
| 4. 빌드 도구 | Tailwind 클래스를 곧바로 모바일 스타일로 볼 수 있는가? | 생성 CSS의 테마 변수·계층·변형·임의 값과 소스 탐지 규칙이 명세되지 않았다. | Tailwind를 CSS 생성 단계로 두고 생성 CSS의 항목별 지원만 인정하도록 명시했다. |
| 5. 문서 간 정합성 | 개요도만 보고 실행 경계와 이벤트 역방향을 구현할 수 있는가? | JS 호스트 API, 스타일 계산과 GPU 장면 생성, OS 입력·IME·접근성 경계가 개요도에 압축돼 있었다. | 별도 모바일 실행 구조도를 추가하고 작성 문법·아키텍처 문서에 연결했다. |

## 계속 남는 검증 항목

- 각 태그·속성·CSS 선언·JS API의 버전별 지원 목록과 오류 형식은 아직 고정되지 않았다. 현재 표는 목표와 제외 범위를 구분한 설계 초안이다.
- 동일 예제의 웹·Android·iOS 화면, 터치·키보드·IME, 접근성 탐색, 백그라운드 복귀를 실제 앱에서 비교해야 한다.
- Tailwind는 생성 CSS를 읽는 경로부터 작은 예제로 검증해야 한다. Preflight, `@layer`, `@theme`, 반응형·상태 변형이 전부 통과하기 전에는 전체 지원으로 표시하지 않는다.
- GPU API, 스레드 소유권, 이벤트 취소의 동기 경계, OTA 패키지의 호환 버전 규칙은 별도 구현 명세가 필요하다.

## 호환성 완료 기준

지원한다고 표시한 기능은 세 플랫폼에서 입력·결과·오류·접근성까지 비교한다. 지원하지 않는 기능은 빌드 또는 개발 실행에서 식별 가능한 진단을 낸다. 결과가 다른 기능은 이름과 차이를 공개한다.
