# 스피논 청크 기반 OTA 설계 초안

**상태:** 목표·계약 초안. 배포 클라이언트·서버는 아직 구현하지 않았다.

## 목표

React Native 앱에서 가능한 JS·스타일·이미지 OTA를 기본 범위로 삼는다. 스피논은 기능별 청크와 콘텐츠 해시를 사용해 변경된 파일만 내려받고, 특정 기능의 변경을 선택한 채널·사용자 집단에 공개할 수 있어야 한다. `부분별 배포`는 전송량과 공개 범위를 줄이는 기능이다. 기기에서 서로 맞지 않는 버전을 섞어 실행하는 기능이 아니다.

## 산출물과 경계

```text
앱 바이너리: V8 + Rust UI 코어 + GPU 렌더러 + OS 호스트 + 내장 릴리스
릴리스 스냅샷: 루트 매니페스트 + 진입점/기능 청크 + 스타일 + 에셋
전송: 기기에 없는 해시의 파일만 다운로드
활성화: 검증된 스냅샷 하나를 원자적으로 선택
```

루트 매니페스트는 앱·플랫폼·채널·릴리스 ID, 바이너리 런타임 ID, 번들 형식 버전, 진입점과 기능 ID, 청크 의존성·해시·크기, 스타일·에셋 해시, 서명 정보를 가진다. 기능은 `feed`, `settings`처럼 안정적인 진입점으로 식별한다. 실제 스키마와 서명 알고리즘은 별도 구현 명세에서 확정한다.

Vite와 Rspack의 청크 형식 차이는 빌드 어댑터가 스피논 배포 형식으로 정규화한다. 빌드 도구의 우연한 파일명이나 청크 분할 결과를 공개 호환 계약으로 삼지 않는다. 모바일 모듈 로더는 활성 스냅샷의 로컬 캐시에서 의존 청크를 해결하고 동적 `import()`를 연결한다. 네트워크에서 받은 JS를 별도 검증 없이 즉시 평가하지 않는다.

## 기능별 배포와 활성화

1. 빌더가 기능 진입점과 공유 의존성을 분석해 새 릴리스 스냅샷을 만든다.
2. 배포 서비스가 대상 플랫폼·런타임 ID·채널·사용자 집단에 스냅샷을 할당한다. 한 기능만 변경했어도 루트 매니페스트는 새 릴리스 ID를 가진다.
3. 클라이언트가 새 매니페스트의 서명과 호환성을 검사한 뒤 없는 해시의 청크·에셋만 내려받는다. 필요한 파일이 모두 준비될 때까지 기존 스냅샷을 사용한다.
4. 다음 앱 시작 또는 안전한 전체 재시작에서 새 스냅샷을 원자적으로 활성화한다. 그 뒤 기능 화면을 처음 열 때 해당 청크를 지연 로딩할 수 있다.
5. 시작 실패나 필수 기능 오류가 확인되면 이전 스냅샷 또는 앱에 내장된 릴리스로 되돌리고 해당 릴리스의 자동 재시도를 중단한다.

기능별 롤아웃은 매니페스트가 가리키는 기능 버전의 조합을 바꾸는 방식이다. 공유 코드나 호스트 API 변경이 다른 기능에 영향을 주면 기능 하나만 독립적으로 승격할 수 없다. 활성화된 V8 모듈의 실행 중 교체와 화면 상태 보존은 개발 HMR 및 별도 후속 연구 범위다.

## 호환성·안전 조건

- OTA 가능: 기존 바이너리의 엔진·호스트 API로 실행되는 JS 청크, 지원 CSS의 스타일 데이터, 이미지·폰트 등 허용된 에셋.
- 바이너리 재배포 필요: V8·Rust/GPU 코어·OS 연결·네이티브 모듈·권한·서명 설정 변경.
- 서로 다른 플랫폼의 산출물을 혼용하지 않는다. 엔진·호스트 API·번들 형식이 맞지 않으면 업데이트를 거부한다.
- 매니페스트 서명과 각 파일 해시를 확인하고, 다운로드 중단·저장 공간 부족·손상 파일·오프라인 시작에서 기존 또는 내장 릴리스를 유지한다.
- CDN 캐시는 불변 해시 파일로 운영하고, 서버의 채널·롤아웃 설정은 별도로 변경한다. 릴리스 중지와 기기 롤백을 구분한다.
- 앱 스토어 정책이 허용하는 앱 목적·기능 변경 범위에서만 OTA를 출시한다. 정책 심사는 기술적 청크 분할과 별개다.

## 구현 관문

첫 수직 구현에서는 단일 번들로 화면·이벤트 계약을 증명하되, 패키징 API는 진입점과 최소 로컬 매니페스트를 받도록 설계한다. 다음 관문에서 이를 청크 그래프와 동적 `import()`로 확장한다. D02에서 서명·채널·롤백에 필요한 릴리스 매니페스트를 완성한다. 배포 관문에서는 한 기능의 JS·CSS·이미지만 변경한 업데이트를 두 모바일 실기기에 보내고, 변경된 해시만 다운로드했는지 기록한다. 다운로드 중단, 공유 청크 변경, 호환되지 않는 호스트 API, 손상 파일, 시작 실패를 각각 재현해 기존 화면과 롤백을 확인한다.
