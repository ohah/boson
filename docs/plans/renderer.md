# GPU 렌더러 구현 계획

**문서 상태:** 구현 계획 초안 · **구현 완료 또는 공개 API 지원을 뜻하지 않습니다.**

이 문서는 GPU 렌더러 작업의 선후 관계와 통과 조건을 정리합니다. 구현 상태는 [`spec/STATUS.md`](https://github.com/ohah/spinon/blob/main/spec/STATUS.md), 공개 동작 계약은 저장소의 버전 있는 `spec/` 문서가 기준입니다. 첫 공식 릴리스 범위는 이 문서에서 정하지 않습니다.

## 1. 책임 경계

| 계층 | 책임 |
| --- | --- |
| 프레임워크 어댑터·제한된 DOM façade | 프레임워크별 갱신과 웹 문법을 공통 호스트 작업으로 변환 |
| Rust 문서·UI 코어 | 안정 노드 ID, 논리 문서 revision, 연결 표시 트리 revision, 스타일과 레이아웃 결과의 revision 소유 |
| `spinon-render` | 일관된 커밋 snapshot을 플랫폼 중립 표시 명령·자원 참조·hit-test 데이터로 변환 |
| Android·iOS 호스트 | GPU 표면과 제출 수명, 플랫폼 입력·IME·접근성 연결, 프레임 결과 보고 |
| 웹 호스트 | 브라우저 DOM과 브라우저 CSS 사용. 모바일 GPU 렌더러를 재사용한다고 가정하지 않음 |

모바일 일반 UI는 GPU로 그리며 태그마다 Android View나 UIKit View를 만들지 않습니다. 표면·IME·접근성·권한·지도·카메라처럼 OS가 제공하는 기능은 플랫폼 경계에서 연결할 수 있습니다. 기존 네이티브 뷰 PoC는 비교 기준으로 보존하며 주 렌더링 경로로 취급하지 않습니다.

## 2. 렌더러 구현 전 선행 계약

다음 항목을 렌더러와 어댑터가 함께 지키는 내부 계약으로 명세한 뒤, 병렬 플랫폼 구현을 시작합니다.

### 트리와 변경 묶음

- DOM·프레임워크가 필요한 경우 문서 루트, 안정 ID, 요소·텍스트 노드의 혼합 순서, 분리 노드 수명과 속성 저장을 정의합니다. 현재 S01 트리의 자식 모델을 DOM 호환 트리로 간주하지 않습니다.
- JS 어댑터가 작업 묶음을 제출하고 commit이 실패·취소·오래된 기준 revision으로 거절될 때 JS와 Rust의 revision 복구 방식을 정합니다. 공개 단계는 중간에 끊지 않는 원자 경계로 둡니다. 취소가 공개 전에 이기면 이전 트리와 revision을 그대로 유지하고 부분 상태를 공개하지 않습니다. 공개가 먼저 끝나면 취소는 늦은 요청이며 해당 revision을 정상 렌더 대상으로 취급합니다. 어댑터가 받는 최종 commit 결과도 실제 공개 상태와 일치해야 하며, 공개된 revision을 취소로 보고할 수 없습니다.
- 렌더 snapshot은 성공적으로 공개된 연결 표시 트리 revision만 읽습니다. DOM의 분리 노드만 바뀌어 논리 문서 revision이 증가해도 현재 표시 트리의 계산을 무효화하지 않습니다. 부분 적용된 작업이나 공개 전에 취소된 연결 트리 갱신은 표시할 수 없습니다. 취소를 공개 직전·직후에 각각 멈춰 두는 결정적 fixture 두 개로 문서·표시 트리 revision·렌더 대상·어댑터가 받은 최종 결과가 일치하는지 확인합니다.

### 스타일·좌표·페인트

- 첫 화면에서 지원할 CSS 속성·선택자·단위·초깃값을 [`0003-web-surface.md`](../../spec/0003-web-surface.md)와 대응표에 고정합니다. 파싱 성공과 화면 지원을 구분하고, 지원하지 않는 속성은 조용히 무시하지 않고 진단합니다.
- 레이아웃 좌표, OS 논리 좌표, 물리 픽셀, 픽셀 비율, 안전 영역, 원점과 반올림 시점을 정합니다. R10의 작은 fixture에서는 Taffy 기본 반올림이 논리 좌표의 소수부를 먼저 없애고, 반올림을 끈 결과는 배율을 적용한 물리 픽셀 경계로 옮길 때 자식 폭을 나누어 배분했습니다. GPU 경로 후보는 레이아웃의 소수 논리 좌표를 유지하고 공용 절대 경계를 래스터 좌표로 변환할 때 배율을 한 번 적용하는 방식입니다. R10은 GPU를 그리지 않았고 Android dp·iOS point를 CSS px에 매핑하지도 않았으므로, 이 후보는 확정 계약이 아닙니다. R08의 실제 GPU 출력·hit-test fixture에서 시각 경계와 입력 경계를 함께 확인한 뒤 확정합니다. [R10 결과](../../spec/internal/evidence/taffy-r10-2026-09-28.md)
- 지원 CSS에 대해 자식 그리기 순서, 겹침, 클립 범위, 변환 합성 순서, hit-test 순서를 같은 규칙으로 정의합니다. `z-index`, 투명도, 위치 지정 등은 명세·fixture가 준비되기 전까지 첫 GPU 화면이 지원한다고 표시하지 않습니다.

### 프레임과 플랫폼 표면

각 프레임 입력은 최소한 다음 식별 정보를 갖습니다.

- 연결 표시 트리·스타일·레이아웃 revision
- 프레임 ID와 GPU 표면 세대
- 표시 명령이 참조하는 자원 ID와 자원 세대
- 제출 시각·완료 결과·오류 또는 폐기 사유

각 단계의 결과에는 출처 논리 문서 revision도 진단용으로 기록할 수 있지만, 표시 최신성은 연결 표시 트리 revision·스타일 revision·레이아웃 revision tuple로 판정합니다. 스타일 결과는 입력 표시 트리 revision을, 레이아웃 결과는 입력 표시 트리 revision·스타일 revision과 결과 레이아웃 revision을 보유합니다. 표시 가능 조건은 스타일 결과의 표시 트리 revision과 프레임의 표시 트리 revision이 같고, 레이아웃 결과의 표시 트리·스타일 revision이 프레임 tuple과 같으며, 결과 레이아웃 revision도 프레임의 레이아웃 revision과 같은 것입니다. 조건을 하나라도 만족하지 않는 늦은 스타일·레이아웃 결과는 폐기하고 필요한 계산을 다시 수행합니다. hit-test와 접근성 bounds도 마지막으로 수락된 프레임의 동일한 표시 트리·스타일·레이아웃 revision 묶음을 사용합니다.

프레임은 내부적으로 생성, 제출 대기, 표시 완료, 대체, 폐기, 실패 상태를 구분합니다. 트리 commit 성공은 화면 표시 완료가 아닙니다. 입력과 접근성 조회는 실제 마지막 표시 프레임을 기준으로 하며, 더 오래된 프레임이 새 프레임 뒤에 표시되지 않도록 합니다. 첫 GPU 화면 전에 플랫폼 호스트가 OS 디스플레이 프레임 시계와 표시 예약기를 제공하고, 트리 공개 뒤 한 번 렌더를 예약하는 경로를 구현합니다. 이 내부 frame driver는 공개 JavaScript `requestAnimationFrame` API의 제공 여부나 의미와 별개입니다.

각 플랫폼 호스트는 동시 제출 프레임 수, 표면 획득 실패·대기·시간 초과, 화면 비활성화 시 대기 작업 취소, drawable/표면 참조의 해제 시점을 정합니다. 프레임 수를 제한하고 표면을 확보한 뒤에만 필요한 제출을 진행합니다. OS·GPU API의 구체 결과는 R08 실험으로 확인합니다.

### 텍스트·자원·OS 입력

- 결정적 Rust 테스트에는 폰트 측정기와 이미지 제공자를 주입할 수 있어야 합니다. 실기기 검증에서는 레이아웃 측정과 GPU 글리프 출력의 shaping·fallback 결과를 대조합니다.
- 이미지의 본래 크기가 바뀌면 영향을 받는 레이아웃 조상과 관련 paint·hit-test·접근성 bounds를 무효화합니다. 노드 제거·이미지 교체·릴리스 전환 뒤 도착한 비동기 결과는 현재 노드·요청·자원 세대와 일치하지 않으면 버립니다.
- GPU 자원은 참조 중인 프레임이 끝나기 전에 해제하지 않습니다. 표면 재생성 뒤 오래된 handle을 사용하지 않으며, 캐시 예산·축출·재업로드·자원 생성 실패 동작을 정합니다.
- 접근성 의미 노드는 시각 노드와 별도로 OS에 노출할 수 있지만 노드 정체성, 역할·이름·값·상태·화면 bounds·활성화 동작·포커스를 정의해야 합니다. 접근성 노드와 hit-test는 같은 표시 frame revision을 사용합니다.
- 편집 가능한 텍스트는 Android 입력 연결과 iOS 텍스트 입력 경계의 포커스·선택·커서·조합·취소·세션 해제 동작을 정합니다. GPU 글자 출력만으로 IME 지원을 완료했다고 판정하지 않습니다.
- OS 제스처의 취소·관성 동작과 JS에 노출하는 웹 유사 이벤트 의미는 별도 계약입니다. JS 이벤트를 지원한다고 표시하기 전에 이벤트 순서, 캡처·버블링, `stopPropagation()`·`preventDefault()`, 포인터 취소 및 키보드·접근성 활성화 순서, 노드 삭제 시 대상, 콜백 수명과 예상 결과를 명세하고 fixture를 고정합니다. OS에서 제스처가 취소되었다는 사실만으로 `pointercancel`을 가정하지 않습니다.

## 3. 단계와 통과 조건

| 단계 | 작업과 선행 상태 | 통과 조건 |
| --- | --- | --- |
| 00 위험 실험 | R06·R08·R10·R13을 Android·iOS 실기기에서 확인 | GPU 표면, 네이티브 프레임 시계에 따른 commit-to-present, 최소 도형, 텍스트 측정, 입력, 회전·복귀 기록과 backend 근거가 있음 |
| 01 트리·레이아웃 계약 | S01/S02와 R03의 트리·원자 commit·좌표 계약을 확정 | 섞인 텍스트 순서가 필요한 범위에서 표현되고, 실패·취소·오래된 commit 및 취소-공개 경합을 결정적으로 재현함 |
| 02 플랫폼 중립 snapshot | Rust 호스트 객체 없이 revision·프레임 ID·명령·자원·오류 생성 | 고정된 측정 fixture로 반복 실행해 같은 입력의 snapshot과 오류가 결정적임 |
| 03 도형·페인트 순서 | CSS 최소 범위의 배경·상자·테두리·변환·클립 중 명세된 항목부터 구현 | 공개된 트리·스타일 revision에 해당하는 레이아웃만 표시하고, 네이티브 프레임 driver로 commit-to-present를 확인함. 이 gate는 공개 JS `requestAnimationFrame`을 요구하지 않음 |
| 04 텍스트·이미지 | shaping·fallback, 이미지 decode/upload, 비동기 무효화와 자원 수명 연결 | 한글·라틴 측정·표시와 이미지 크기 변경·실패·늦은 응답을 기기에서 확인함 |
| 05 입력·접근성·IME | hit-test, JS 콜백, OS 의미 노드, 텍스트 입력 경계 연결 | stale revision, 노드 삭제, 포커스·조합 취소와 보조 기술 활성화의 기대 결과를 검증함. JS 이벤트 호환을 표시하려면 이벤트 계약 fixture도 먼저 고정함 |
| 06 스크롤·제스처·애니메이션 | U07·E06 범위. 첫 정적 GPU 화면의 필수 조건으로 앞당기지 않음 | 스크롤 오프셋이 화면·hit-test·접근성에 같게 반영됨. 공개 JS `requestAnimationFrame`·`cancelAnimationFrame` 의미와 중첩 제스처·취소를 별도 계약과 fixture로 검증함 |
| 07 복구·자원·부분 갱신 | E01–E07·S11, 표면·기기 메모리 압박과 프레임 취소 | 회전·백그라운드·표면 손실·자원 축출 뒤 누수·오래된 handle·오래된 화면 성공 보고가 없음 |
| 08 적합성·비교 | R05·S07·S09와 공통 benchmark fixture | 웹·Android·iOS 결과와 실기기 측정 원본이 같은 조건으로 남고, 기능 차이가 있으면 순위를 매기지 않음 |
| 09 OTA 연결 | R15·D02·D04와 [정식 OTA 설계](../ota-design.md)를 따르며 렌더러 첫 화면 이후 연결 | 검증된 불변 릴리스 snapshot의 release ID·manifest digest·binary runtime ID와 JS/CSS/폰트/이미지 해시를 프레임·자원 세대에 묶음. 렌더러는 digest를 불투명한 snapshot 식별자로만 소비함. digest의 생성·표준화와 서명 검증은 OTA 계약 소유이며, 아직 정의되지 않은 부분은 R15/D02에서 고정한 뒤 통과시킴 |

스크롤·애니메이션·OTA를 아직 구현하지 않은 단계에서는 이를 지원으로 표기하지 않습니다. 이미지나 폰트를 포함하지 않는 단계에서는 해당 자원 완료를 화면 표시의 필수 조건으로 가장하지 않습니다.

| commit 취소와 공개가 경합하는 두 순서 | 공개 직전 취소에서는 이전 트리·revision과 취소 결과를 유지하고, 공개 직후 취소에서는 새 revision과 성공 결과를 유지함. 어댑터 결과와 트리 상태가 일치하며 부분 트리가 없음 | R03, R06, S01 |
| 새 표시 트리·스타일 도착 뒤 이전 스타일·레이아웃 계산 완료 | 캡처한 입력 revision이 현재 frame tuple과 하나라도 다르면 결과를 거부하고, 화면·hit-test·접근성이 같은 수락된 revision tuple을 사용함 | R03, R10, E01, E03 |
| 분리 노드 생성·수정 도중 연결 트리 레이아웃 계산 완료 | 논리 문서 revision만 증가한 동안 기존 계산을 계속 수락할 수 있고, 노드가 표시 트리에 연결된 뒤에는 새 표시 트리 revision으로 이전 결과를 거부함 | R03, R06, E01 |
| 이미지·글리프 업로드 도중 노드 삭제와 표면 재생성 | 제출 중 자원은 안전하게 유지되고 오래된 응답·handle은 버리며 새 세대에서 재생성함 | R08, R13, S11, E02, E07 |
| OTA 뒤 이전 릴리스의 이미지·폰트 응답 도착 | 활성 immutable snapshot의 release ID·manifest digest·runtime ID·JS/CSS/폰트/이미지 해시가 모두 일치하는 자원만 새 프레임에 포함하고, 불일치는 거부·롤백함 | R15, D02, D04 |

상세 측정은 [네 구현 비교 벤치마크 계획](benchmark.md)의 실기기·릴리스 빌드·주사율·발열·반복·측정 오차 규칙을 사용합니다. 렌더러 계획은 그 계측 조건을 새로 정의하거나 대체하지 않습니다.

## 5. 공식 체크리스트와의 연결

공식 상태를 별도로 복제하지 않고 기존 ID를 사용합니다.

| 상태 ID | 렌더러 계획에서 다루는 범위 |
| --- | --- |
| R03·R06 | 공통 트리 작업, commit 복구, revision·스레드·수명 계약 |
| R05·R08·R10·R13 | 계측, GPU·Taffy·좌표 위험, 표면·자원 복구 실험 |
| S01·S02·S04 | 트리·레이아웃 선행 조건과 Android/iOS GPU 적용기 |
| S05·S07·S09·S11 | React 연결, 텍스트·입력·접근성, 네 구현 비교, 수명 복구 |
| U07·E01–E07 | 스크롤, 부분 갱신, GPU 자원, 이벤트·제스처·프레임 예약 |
| R15·D02·D04 | OTA의 릴리스·자원 호환, 원자 활성화와 롤백 |

이 문서에 적힌 통과 조건은 상태 대장의 완료 체크가 아닙니다. API 또는 내부 인터페이스를 완료로 표시할 때는 해당 동작을 버전 있는 `spec/` 명세와 실행 근거에 연결해야 합니다.
