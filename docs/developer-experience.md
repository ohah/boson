# 스피논 개발 경험: 리로드, HMR, JS 디버깅

이 문서는 구현 목표다. 현재 V8·트리 PoC에 모바일 HMR이나 CDP 서버가 구현됐다는 뜻이 아니다.

개발자가 실행할 명령과 에이전트가 조회할 도구는 [CLI·MCP 설계](cli-mcp.md)에 분리한다.

## 개발 연결의 경계

```text
Vite 또는 Rspack 개발 서버
  ├─ JS·CSS·에셋 변경과 소스맵
  └─ 개발 연결(기기 인증·버전 확인·변경 통지)
       ↓
Android / iOS 개발 빌드
  ├─ 모듈 로더와 스타일 데이터 교체
  ├─ V8 Inspector ↔ 디버그 전송 ↔ Chrome DevTools
  └─ 스피논 UI 트리·스타일·레이아웃 계측
```

개발 연결은 개발 빌드에서만 활성화한다. 기기와 개발 서버의 발견·인증·재연결, 전송 실패, 앱 백그라운드 상태를 별도 계약으로 둔다. 릴리스 빌드와 OTA 경로에는 디버그 서버가 없다.

## 단계 1 · 저장 후 전체 리로드

첫 세 플랫폼 카운터 화면에서는 파일 변경 → Vite 개발 서버 재빌드 → 모바일 앱에 새 번들 통지 → JS 문맥과 스피논 UI 트리 전체 리로드 → 오류 또는 새 화면 표시를 먼저 구현한다. 콘솔, 빌드 오류, 런타임 스택과 소스맵의 원본 위치를 함께 확인한다. 전체 리로드는 컴포넌트 상태를 보존하지 않는다.

## 단계 2 · HMR과 프레임워크별 상태 보존

Vite의 `import.meta.hot`이나 Rspack의 HMR 런타임은 변경 모듈을 알려준다. 모바일에서는 별도의 모듈 등록·수락·정리·교체·참조 무효화와 개발 전송이 필요하다. CSS 변경은 새 모바일 스타일 데이터의 유효성을 확인한 뒤 스타일·레이아웃 무효화로 반영한다. 이미지·폰트 변경은 에셋 캐시와 GPU 자원을 함께 갱신한다. 네이티브 코드·V8·GPU 렌더러·호스트 ABI 변경은 앱 재빌드가 필요하다.

React의 상태 보존은 HMR 자체와 별도인 Fast Refresh 통합으로 검증한다. 컴포넌트 경계가 깨지거나 모듈 교체가 실패하면 오류를 보여주고 전체 리로드로 복구한다. Vue·Svelte는 각자의 컴파일러·HMR 계약을 어댑터별로 확인한다. 상태가 보존되는 조건과 리로드되는 조건을 문서화한다.

## 단계 3 · V8 Inspector와 CDP 범위

V8 Inspector는 JS 디버깅을 위한 프로토콜 연결 지점을 제공한다. 스피논은 Inspector 세션 수명, 메시지 전송, 개발 기기 연결과 소스맵 URL을 구현해야 한다. 첫 지원 목표는 JS 중단점, 단계 실행, 호출 스택, 콘솔, 예외, JS 프로파일링이다.

Chrome DevTools에서 JS를 디버깅할 수 있다는 것이 브라우저 전체 CDP 지원을 뜻하지 않는다. 스피논에는 DOM·브라우저 문서가 없으므로 `DOM`, `CSS`, `Page`, `Network` 도메인의 브라우저 동작을 자동으로 제공하지 않는다. UI 계층을 보려면 스피논 노드 ID, 계산된 스타일, 레이아웃, 접근성 의미, 프레임 시간을 노출하는 별도 조사 도구가 필요하다. 네트워크 요청 표시는 스피논 `fetch` 구현과 별도 계측을 연결한 뒤 지원 여부를 명시한다.

## 후속 도구 · 개발용 미리보기와 분석

Lynx Explorer와 같은 개발용 미리보기 앱은 HMR과 다른 항목이다. Android·iOS에 미리 설치한 스피논 개발 호스트가 QR 코드나 번들 URL로 개발 서버에 연결해 화면을 열고, 리로드와 오류를 보여준다. S12의 개발 연결과 S13의 CLI가 먼저 필요하다. 초기에는 S06 단일 번들용 개발 매니페스트로 런타임·네이티브 API 버전을 확인하고, X01의 청크 로더가 생기면 개발 매니페스트의 청크 참조를 확장한다. D02의 서명된 릴리스 매니페스트는 선행 조건이 아니다. 네이티브 코드나 호스트 ABI가 바뀌면 앱을 새로 빌드해야 한다. 이 앱은 릴리스 OTA의 배포 수단이 아니다.

UI 조사는 X13의 노드 조회를 화면 선택·강조 표시·원본 TSX/JS 위치 연결로 확장한다. 소스 위치는 Vite·Rspack 빌드 메타데이터와 소스맵에서 가져오고, 계산된 스타일·박스 모델·적용되지 않은 규칙을 스피논 스타일 엔진의 결과로 보여준다. 브라우저 Elements 패널을 그대로 지원한다는 뜻은 아니다. 빌드 분석은 별도로 청크·CSS·에셋 크기와 빌드 단계 시간을 Vite·Rspack에서 비교 가능한 형식으로 출력한다. 런타임 프레임 계측과 빌드 시간 계측을 섞지 않는다.

## 완료 판정

| 기능 | 확인할 결과 |
| --- | --- |
| 전체 리로드 | Android·iOS 실기기에서 저장 후 변경 화면 또는 원본 위치가 있는 오류가 나타난다. 연결이 끊겼다가 복귀해도 최신 번들로 회복한다. |
| JS HMR | 수락 가능한 모듈만 교체되고 정리 콜백이 한 번 실행된다. 제거한 이벤트·타이머·노드 참조가 남지 않는다. 실패하면 전체 리로드한다. |
| React Fast Refresh | 지원되는 컴포넌트 편집에서는 상태가 유지되고, 지원되지 않는 편집에서는 이유와 함께 리로드된다. |
| CSS·에셋 갱신 | 스타일 변경이 전체 앱 재설치 없이 보이며 이전 GPU 자원과 캐시가 해제된다. |
| JS 디버깅 | Chrome DevTools에서 두 모바일 플랫폼의 원본 TSX/JS 위치에 중단점이 걸리고 스택·예외·콘솔·프로파일이 맞게 보인다. |
| UI 조사 | 스피논 노드와 스타일·레이아웃·접근성 값을 선택해 확인할 수 있다. 브라우저 Elements와 혼동하지 않도록 별도 표시한다. |
| 개발용 미리보기 앱 | Android·iOS의 사전 빌드된 호스트에서 호환되는 번들을 QR 코드나 URL로 열고 리로드·오류를 확인한다. 호환되지 않는 ABI는 실행 전에 거부한다. |
| 소스 연결 UI 조사 | 기기에서 고른 노드가 원본 TSX/JS 위치와 연결되고, 계산된 스타일·박스 모델·적용되지 않은 규칙을 확인할 수 있다. |
| 빌드·번들 분석 | Vite·Rspack 빌드에서 청크·CSS·에셋 크기와 빌드 단계 시간을 같은 단위로 출력한다. |
