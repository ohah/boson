# 0004 · 실행·빌드·배포

**상태:** 제안 · **명세 버전:** `0.1.0-draft`

## 모바일 실행 경계

모바일 앱은 V8 어댑터, 프레임워크 어댑터, Rust UI 코어, 스타일·레이아웃, GPU 렌더러, Android·iOS 호스트를 별도 책임으로 둔다. 첫 엔진 목표는 Android·iOS의 같은 V8 소스 리비전이며 iOS 실기기에서는 JIT 없는 실행을 확인해야 한다.

OS 호스트는 GPU 표면, 입력·IME·접근성 연결을 제공한다. 일반 요소는 GPU로 그리지만 WebView·지도·카메라 등은 명시적인 플랫폼 컴포넌트다. 화면 회전·백그라운드 복귀·GPU 표면 재생성의 복구와 실패 표시가 첫 모바일 앱의 적합성 항목이다.

## 빌드 산출물

| 대상 | 산출물의 의미 | 첫 구현 범위 |
| --- | --- | --- |
| 웹 | 같은 앱 코드의 브라우저 DOM·CSS 빌드 | React·Vite |
| 모바일 JS | V8에 전달할 JS와 소스맵·에셋 참조 | 개발·릴리스 단일 번들 |
| 모바일 스타일 | 지원 CSS만 담은 버전 있는 스타일 데이터 | 카운터 화면 최소 집합 |
| 앱 바이너리 | V8, Rust 코어, GPU 렌더러, 플랫폼 호스트 | Android·iOS 실기기 |

`단일 번들` 적합성은 ESM 청크 로딩이나 동적 `import()` 적합성을 뜻하지 않는다. Rspack, 여러 청크, Vue·Svelte의 산출물은 별도 적합성 대상이다. 웹과 모바일은 원본 코드가 같아도 플랫폼별 산출물은 다르다.

## 번들·호스트 호환성

매니페스트에는 적어도 번들 형식 버전, 필요한 호스트 API 버전, JS·스타일·에셋 해시와 대상 앱 버전을 기록하는 방향을 제안한다. 실제 필드 형식, 서명 형식, 호환성 거부 오류는 **미정**이다. 빌드는 미지원 요소·CSS·API를 식별 가능한 위치와 함께 진단해야 한다. 빌드 도구가 발견하지 못하는 동적 참조는 런타임 오류 계약도 필요하다.

## OTA

OTA는 개발 HMR과 별개의 릴리스 배포 경로다. 서명·무결성·호환 버전 확인, 원자적 교체, 실패 감지와 롤백을 설계한다. 플랫폼 정책과 앱 기능 변경 범위가 허용된 경우에만 제공한다. OTA가 불가능한 배포 대상에서는 앱 바이너리 업데이트 경로를 사용한다. 이 명세는 스토어 심사 승인이나 모든 JS 기능 변경의 허용을 주장하지 않는다.
