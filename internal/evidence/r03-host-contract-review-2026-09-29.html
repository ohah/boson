    #R03 공통 호스트 계약 검토 기록 — 2026-09-29

    #산출물

    • 내부 인터페이스 0003 · 공통 문서·호스트 계약 초안
    • UI 트리·이벤트 제안
    • 모바일 DOM 호환 제안
    • 대조한 구현·계획: S01 Rust 트리 코어, GPU 렌더러 구현 계획, 모노레포 구현 계획

    이 작업은 내부 설계 문서 산출물입니다. 실행 코드, 앱 작성 API, 브라우저·시뮬레이터 동작의 구현 증거는 추가하지 않았습니다.

    #최초 적대적 검토 5회

    1. 정본(SSOT)과 문서 경계: spec/README.md와 내부 명세 목록이 이 문서를 공개 API가 아닌 내부 경계 제안으로 분류하도록 고쳤습니다. 상태 대장은 R03 초안 산출물만 완료로 기록하고, 0002·0007은 공개 동작 제안으로 남깁니다. 내부 초안은 공개 지원 표가 아닙니다.
    2. Rust 자료 모델: 현재 S01의 Tree는 단일 연결 루트와 파괴적 하위 트리 제거를 사용합니다. DOM은 요소·Text 혼합 순서, 분리 노드 재삽입, JS 래퍼 객체 정체성을 요구하므로 기존 Operation::Remove를 DOM removeChild()로 직접 연결하지 않도록 detach와 dispose를 분리했습니다.
    3. JavaScript 변환과 동기 의미: DOMString의 UTF-16 코드 단위 보존, 시그니처별 null·undefined·Symbol 변환, 변환 후 원자 변경, 성공 직후 동기 논리 조회를 적었습니다. Rust UTF-8 문자열만으로는 단독 서로게이트를 보존하지 못할 수 있음을 경계 제약으로 드러냈고, GPU 표시 완료·레이아웃 측정은 동기 호출에 넣지 않았습니다.
    4. CSS·revision·이벤트: 최초 검토에서 Text 데이터가 :empty 같은 지원 선택자의 결과를 바꿀 수 있는 무효화 누락을 찾아 문서 전체 스타일 재계산 제안으로 보완했습니다. 속성·구조·텍스트 변경의 무효화 단계를 구분하고 비동기 결과를 입력 revision에 묶었습니다. 오래된 표시 프레임의 이벤트가 분리된 대상을 가리키면 폐기하고 다시 대상을 정하지 않는 제안을 두었습니다. 캡처·버블·취소와 정확한 스타일 범위는 공개 적합성 결정으로 남겼습니다.
    5. 어댑터 소유권·열린 결정: 같은 문서에서 서로 다른 소유자의 형제 트리를 허용하고 소유자가 다른 트리의 수정은 원자적으로 거부하도록 제안했습니다. 앱 루트와 허용 자식, 다중 루트·포털, 직접 DOM 호출의 소유자 판별, V8 GC와 이벤트 수신기 회수, 작업 실행기 스레드, 입력 좌표와 취소 경합은 미정으로 남겨 R06·S03 및 사용자 범위를 앞당겨 확정하지 않았습니다.

    #판정

    다섯 관점에서 찾은 자료 모델 충돌과 문자열 표현 위험을 문서에 반영했습니다. 현재 S01을 직접 DOM 구현으로 취급하지 않으며, 공개 API 동작 완료·호환성·제품 지원을 주장하지 않습니다. 이 검토는 문서 내부 일관성만 확인했고 런타임 적합성은 검증하지 않았습니다.

    #추가 적대적 검토 5회 — 2026-09-29

    1. SSOT와 완료 상태: spec/STATUS.md의 R03 완료는 내부 초안 산출물만 가리키고 공개 지원 API·런타임 구현은 미완료임을 재확인했습니다. 네이티브 모듈 계약은 별도 X08/J15 작업으로 남아 있어 이 DOM 호스트 계약에 구현 완료로 섞이지 않습니다.
    2. DOM 삽입 경계: 기존 초안은 잘못된 삽입 위치를 거부한다고 했지만 기준 자식 검증, insertBefore(node, node), 같은 부모 안의 인덱스 이동을 구체화하지 않았습니다. 검증·위치 정규화 후 원자 적용하도록 초안을 보완하고 관련 적합성 사례를 미결정 목록에 추가했습니다. WHATWG DOM의 pre-insert 동작을 참고 링크로 명시했습니다.
    3. 논리 상태와 화면 revision: 분리 노드 변경도 논리 revision을 올리면서 현재 화면을 무효화하지 않는다는 두 규칙이 충돌했습니다. DocumentRevision과 연결 표시 트리 RenderTreeRevision을 분리하고, 비동기 표시 계산은 표시 트리 revision을 기준으로 수락하도록 내부 계약과 GPU 렌더러 계획을 함께 고쳤습니다.
    4. CSS·프레임·입력: 속성·구조·텍스트 변경 표가 여전히 지원 범위 안에서 계산을 무효화하며, 입력 대상은 실제 표시 프레임에서 판정돼야 함을 확인했습니다. 이벤트 envelope에 표시 트리 revision을 명시했습니다. 현재 트리 변경과 지연 이벤트가 경합할 때의 최종 전달 규칙은 S05 미결정으로 유지했습니다.
    5. V8·네이티브 모듈·OTA 경계: 내부 DOM 호출과 앱의 플랫폼 모듈 호출은 다른 표면입니다. 현재 공개 방향은 타입이 있는 JS/TS API, 빌드 바인딩, 플랫폼 등록, Isolate로 비동기 결과 전달이며, 등록 형식·큐·취소·모듈 수명·호스트 버전/OTA 호환은 X08/J15에서 결정해야 합니다. R03이 이를 이미 구현했거나 JSI를 공개 API로 제공한다고 오해할 문구는 추가하지 않았습니다.

    이번 다섯 회차에서 확인한 두 결함(삽입 위치 의미의 빈칸, 논리/표시 revision 충돌)을 내부 계약·관련 상태 및 렌더러 계획에 반영했습니다. 남은 미결정 항목은 0.1.0-draft와 상태 대장에 공개적으로 유지합니다. 검토는 문서·계획 내부 정합성 확인이며 런타임 적합성 검증은 아닙니다.

    #세 번째 추가 적대적 검토 5회 — 2026-09-29

    1. SSOT·테스트 준비도: tests/README.md에 공통 픽스처 형식은 호스트·이벤트 계약 확정 뒤 정의한다고 적혀 있고 tests/에는 README만 있습니다. R03의 예상 시나리오는 실행 테스트가 아니므로, 픽스처를 임의로 만들거나 실행 증거로 표시하지 않았습니다. 이번 브랜치 변경은 명세·계획 문서뿐이고 Document API 호출이나 런타임 테스트는 없습니다.
    2. revision 초기 상태: RenderTreeRevision의 초기값이 계약에 없었습니다. DocumentRevision과 모두 0에서 시작한다고 보완했습니다.
    3. 다중 Owner 변경 충돌: 전역 DocumentRevision을 낙관적 기준으로 쓰면 독립된 OwnerId 하위 트리의 동시 계산이 불필요하게 서로의 묶음을 거부할 수 있음을 드러냈습니다. 소유자별 revision, 직렬 제출·재동기화와 거부 후 복구는 R06의 명시적 결정·시나리오로 남겼습니다.
    4. 트리 밖 레이아웃 입력: 화면 크기·배율·안전 영역·시스템 글꼴 크기 변화는 문서 revision 없이 계산 결과를 바꿀 수 있습니다. 렌더러 계획에 환경 revision과 오래된 계산 폐기 조건을 추가하고, 최종 입력 계약은 버전 있는 spec/에 기록하도록 SSOT 경계를 명시했습니다.
    5. 큐에 남은 입력 이벤트: 대상이 계속 연결돼 있지만 입력 프레임 뒤 이동·숨김된 경우의 처리 기준이 예상 시나리오에 없었습니다. 케이스를 추가하고 전달·폐기 결정은 S05 미결정으로 유지했습니다.

    이번 회차에서 초기 revision 값은 정했고, 전역 revision 충돌·환경 입력 revision·연결 상태가 바뀐 지연 이벤트는 구현 전 해결할 항목과 향후 판정 사례로 명시했습니다. 이 검토도 문서 정합성 확인이며 동작 테스트는 아닙니다.

    #문서 검사

    • 최근 추가 변경 뒤 변경 문서의 로컬 링크 대상과 git diff --check를 확인했습니다.
    • tests/README.md만 존재하며 공통 fixture 형식과 런타임 테스트는 아직 없습니다. 이번 문서 전용 변경에서는 테스트를 실행하지 않았습니다.
