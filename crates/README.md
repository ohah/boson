# Rust 워크스페이스

루트 [`Cargo.toml`](../Cargo.toml)이 Rust 워크스페이스입니다. `spinon-core`는 실험용 `Tree`, 내부 우선순위 선택기와 R03 `HostDocument` 모델을 소유합니다. `HostDocument` snapshot은 C03에서 Stylo DOM·selector adapter에 연결했습니다. `spinon-style`은 기본 CSS 자원과 Stylo stylesheet 파싱·출처·등록 순서를 소유하고, C04.1 fixture에서 cascade·computed style을 고정 Chromium reference와 비교합니다. `spinon-style-to-layout`은 revision이 일치하는 computed-style profile을 제한된 `LayoutStyle`로 변환해 `spinon-layout`에 전달합니다. `spinon-layout`은 S01 `Tree` 또는 HostDocument 요소 하위 트리를 Taffy 입력으로 투영해 프레임을 계산합니다. `spinon-render`는 플랫폼·GPU 의존성이 없는 불변 CSS px 장면 snapshot 자료형을 소유하며, `spinon-style-to-render`는 S04 고정 fixture의 Stylo paint와 Taffy frame을 revision·노드 집합 검사 후 결합합니다. 이 연결은 내부 CPU fixture까지이며 Android/iOS GPU 표면, 제품 runtime, 공개 CSS API나 일반 CSS 적합성을 구현하지 않습니다. `spinon-runtime`은 V8 세션·작업 큐·Isolate 소유 스레드를, `spinon-ffi`는 플랫폼 C ABI와 입력·출력 변환을 소유합니다. 의존 방향은 `spinon-style → spinon-core`, `spinon-style-to-layout → spinon-style + spinon-layout + spinon-core`, `spinon-layout → spinon-core`, `spinon-render → spinon-core`, `spinon-style-to-render → spinon-style + spinon-style-to-layout + spinon-render + spinon-core`, `spinon-ffi → spinon-runtime → spinon-core`입니다. 공개 앱 API는 아직 제공하지 않습니다. 실제 코드·내부 계약·테스트가 준비된 크레이트만 구성원으로 추가합니다.

예정 구조와 작업 순서는 [모노레포 구현 계획](../docs/plans/implementation.md)을 참고합니다. 공식 구현 상태와 완료 판정은 [상태 대장](../spec/STATUS.md)만 기준으로 삼습니다.
