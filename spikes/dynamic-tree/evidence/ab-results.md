# 실제 보손 코어의 ID 검색 A/B 검증

## 변경과 측정 범위

기존 Rust `Tree`는 `Vec<Node>`에서 ID를 찾을 때 선형 검색한다. 실험 변형은 `HashMap<ID, Vec 위치>`를 생성·삭제와 함께 유지하고 동일한 `Tree`·V8·플랫폼 호스트에서 ID 조회에 사용한다. `boson_indexed` 컴파일 플래그 외에 JS 화면과 터치 로직은 같다. 인덱스 맵은 이벤트 스냅샷에도 함께 복제한다.

Android 16 실기기 Samsung `SM-S731N`과 iPhone 17 Pro iOS 26.2 시뮬레이터에서 버튼 1개와 텍스트 100·1000·5000개를 만들었다. 각 조건은 앱을 새로 설치·시작한 뒤 버튼이 텍스트 1개와 동적 노드 1개를 바꾸도록 20회 성공 터치했다. A/B 순서를 바꿔 3회 반복했다. 표의 값은 **각 실행에서 20개 이벤트의 중앙값을 구한 뒤, 3개 실행 중앙값을 다시 취한 값**이다. 단위는 ms다.

이 문서의 iOS 시뮬레이터용 V8은 `v8_jitless = false`로 빌드했다. [JIT 없는 시뮬레이터 재측정](ios-jitless-results.md)은 별도 결과로 보관한다.

`snapshot`은 Rust 트리 전체 복제, `dispatch`는 그 복제를 포함한 V8 이벤트 처리, `render`는 실제 Rust 레이아웃 순회와 JNI/Android 또는 UIKit 뷰 적용을 포함한다. `core`는 실제 렌더 **후** 같은 트리에 대해 빈 콜백으로 레이아웃을 한 번 더 실행한 독립 계측이다. 따라서 `render - core`를 정확한 뷰 적용 시간으로 해석할 수 없다. Android PSS는 이벤트 20회 뒤 프로세스에서 기록했다.

Android 5000개에서 코어 전용 레이아웃은 약 **17.6배**, iOS 시뮬레이터는 약 **34배** 짧아졌다. 하지만 실제 `render`는 각각 약 **17%**와 **38%** 감소했다. 나머지 시간에는 모든 네이티브 뷰에 프레임·텍스트·접근성 설명을 적용하는 작업과 호스트 호출 비용이 포함된다. 현재 앱은 화면 밖 5000개 뷰도 매 이벤트마다 갱신하며 스크롤·재사용을 제공하지 않는다. 스냅샷과 이벤트 처리 시간은 인덱스 맵 복제로 조금 늘어나는 조건이 있었다. Android PSS 차이는 실행 간 변동 범위와 비슷해 메모리 우열을 결론 내릴 수 없다.

Android `nativeCreate`부터 최초 네이티브 뷰 생성까지의 5000개 조건 중앙값은 선형 184.9ms, 인덱스 156.6ms였다. 앱 실행부터 첫 화면 표시까지의 콜드 스타트는 포함하지 않는다. `render`와 `core` 모두 화면의 실제 픽셀 표시 완료 시각을 뜻하지 않는다.

입력은 200ms 간격으로 주입했다. Android 모든 조건에서 20번 주입해 20번 성공 콜백을 얻었다. iOS 시뮬레이터 5000개 조건은 선형·인덱스 양쪽 모두 매 반복에서 주입 21번에 성공 콜백 20번이었으며 접근성 카운터도 20이었다. 별도의 빠른 Android 5000개 선형 검색 시도에서는 20회 주입 중 [성공 콜백 14회](ab/android-5000-unpaced-scan.log)만 기록됐다. 이는 입력 주입 방식과 메인 스레드 부하가 섞인 관찰이며, 사람의 터치 손실률이나 플랫폼 간 우열로 일반화할 수 없다.

## 검증 자료와 재현

선형·인덱스 양쪽 Rust 경계 테스트 6개씩 통과했다. 반복 실행은 노드 수·컴파일 변형·성공 터치 20건·프레임 노드 수를 검사한다. Android·iOS의 [집계 원본](ab/android-probe.jsonl)과 [iOS 원본](ab/ios-probe.jsonl)에 이벤트별 수치·입력 횟수·원본 로그 파일명을 기록했다. 예를 들어 [Android 5000 선형 로그](ab/android-probe-5000-r3-scan.log)와 [인덱스 로그](ab/android-probe-5000-r3-indexed.log)에서 개별 값을 확인할 수 있다.

로컬 Mac에서 다음을 실행한다. `build-ab.sh`는 각 플랫폼의 선형·인덱스 앱을 `build/dynamic-tree/ab`에 별도로 저장한다. 실기기는 USB로 연결하고 iOS 시뮬레이터는 하나만 부팅한다. Android용 공식 V8, SDK/NDK, iOS 시뮬레이터용 공식 V8은 기존 PoC 빌드 문서의 입력이 필요하다.

```sh
bash spikes/dynamic-tree/build-ab.sh
python3 spikes/dynamic-tree/measure-ab.py android --serial <기기-ID>
python3 spikes/dynamic-tree/measure-ab.py ios
python3 spikes/dynamic-tree/analyze-ab.py spikes/dynamic-tree/evidence/ab/*-probe.jsonl
```
